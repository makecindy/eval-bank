# 产品说明

这是一个远程文件工作区。用户从不同设备浏览自己的文件，打开HTML及其资源，也会把文件交给其他页面或暂存为附件。可能同时打开多个页面、修改文件、退出页面或重新打开。单个资源或一次操作失败后，其他操作仍应可用。

文件内容以来源设备为准；账号、设备和工作区之间不能串用内容。SSH入口只能访问配置的工作目录。预览是只读使用，不改写来源文件；服务仅供授权的本地页面使用。用户结束操作后无需等远端恢复，其余使用者仍能继续自己的操作。

缓存的目的是减少重复取回。未变化且仍驻留的文件允许复用，同一版本的活跃使用者应共享取回。文件版本由完整size和mtimeMs确定，时间可带小数；不要求识别二者都不变的内容变化。调用方拿到的文件路径在容量允许时应继续对应那份内容。容量目标4GiB，按最近使用回收。沿用该切片的历史行为：刚成功返回的文件在本次回收中受保护；它单独超过目标时可以暂时超额，其余旧文件应回收，后续启动清扫仍按目标回收。本项目不承诺超过容量后永久保留打开中的文件。

曾成功取得的旧副本可用于离线读取，但不能据此断言它与当前远端版本完全一致。历史格式为<来源hash>-<size>-<取整mtime>-<basename>。可识别来源的历史副本仍可离线读取，但不能直接作为精确在线命中。更早的无设备归属数据不可猜测归属，容量允许时保留原件并在线重新获取。历史来源hash为SHA256换行连接字段的前20个十六进制字符；字段依次为scope、transport、endpointId、workdir、relPath；更早格式缺endpointId。含换行的旧字段分界不可靠，不要求自动迁移。物理文件命名属于内部实现，可改变，但不能误认旧数据的含义或破坏离线可读性。

名称来自用户文件，允许中文、emoji、长名称和普通扩展名。文件系统组件长度按UTF-8字节计，本环境上限255字节；需要缩短时应保留完整字符和正常扩展名。下载器即使接到取消信号也可能稍后返回成功、失败或进度；接口调用者不保证远端配合及时退出。

实现可以自行选择缓存和发布方式，验收不要求固定算法、锁或文件名。行为声明不能仅靠吞错、禁用复用、移除容量限制、截断正文或放宽权限来满足。

工作台以本地目录与回环HTTP承载真实文件读写和预览；runtime只是固定宿主适配。Node strip-types构建仅检查解析和加载，不是完整tsc，也不证明真实SSH/设备、Windows、原生UI或性能。

合法文件可以以 .part 结尾；成品、未完成传输和无法判定归属的旧文件应按其意义处理。inline写穿是可失败的优化，但不能把长度不符合远端元数据的内容发布为成功缓存。用户提供的来源字段必须无歧义，名称大写和普通扩展名也应保留。
