# 产品使用与接口

## 用户可见行为
同一任务的新消息、工具结果、文件和卡片，应反映当前输入。各任务不得串内容。结束后的正文可以接替工具图片展示；仍在生成的正文尚未承担这份展示职责，不能提前撤掉工具媒体。卡片应属于实际发起它的工具调用；历史无调用 ID 的卡片允许按插件身份匹配，但有明确调用 ID 的卡片不能配给别的调用。卡片是否接替工具行取决于是否已有结果和明确状态，详见下文。

用户切换工作目录、任务模式、历史窗口或者账号后，内容仍正确。用户可以修改提取后媒体列表的结构而不影响别处；不要求随意修改嵌套对象的隔离。

## 卡片与媒体的既有展示取舍

以下是产品约定，不是要求新增的功能：

- 工具结果已带卡片 ID 时，`byCallId` 中对应项为 `ready` 才展示卡片；为 `loading` 或尚无记录时，暂不展示该工具行和其媒体，避免加载过程中先展示后撤回造成闪烁。明确为 `missing` 才恢复原工具行和媒体兜底。未知与明确缺失不是同一状态。
- 工具尚未返回结果时，live card 只有在对应记录 `ready` 时才接替工具行；未就绪的 live card 不接替。这个分支与“结果已经声明了卡片 ID”的分支不同。
- 有明确工具调用 ID 的卡片只属于该调用；无调用 ID 的历史卡片才允许按插件匹配。接口状态只有 `ready`、`loading`、`missing`，不要自行假定存在 `pending` 状态。
- 工具图片是否由正文接替，以同一轮 assistant 消息的 `isStreaming` 为准：仍在生成时保留工具图片，不在生成时才按正文中的图片去重。历史消息可以没有 `turnCompleted`；不能因此把非流式正文永久当作未完成。

这些取舍只约束可见输出，不规定缓存内部写法。

## 输入生命周期
消息 content 是必填字符串；消息/任务更新/变更集采用不可变发布：更新对象或数组会更换引用，未变对象可以共享。clientId 在一条消息的生命周期内稳定，不代表内容不再变化。卡片快照含 version，Map 可复用；变化时发布新快照和新 version。属主 API 的 generation 表示一次数据生命周期，同一账号重新登录也会变；相同账号和相同 generation 的重复设置是幂等操作。调用方传入的消息只读。

src/entry.js 是工作台入口。内部模块可独立调用以定位问题，但验收覆盖真实投影调用链，不能只修表面输出。每次挂载的 Markdown 解析容器可以更换，不应仅因辅助容器变化就重建相同历史。一次完整投影内多个消费者也可能访问同一文本。

## 工作量与驻留约束
这份产品切片已有缓存优化目标。未失效且未被淘汰的数据，热访问不重复完整投影、完整 JSON 或 Markdown 解析；变化的数据必须重新得到正确结果。无元数据标记的普通工具文本不需要 JSON.parse。合法、空和无效结果都要遵循正常输入语义。相同不可变消息片段与上下文重复投影，应复用文件收集工作，即使外层消息数组因流式尾巴而更新。

元数据缓存最多512条；完整历史投影最多3份，采用最近使用策略。两者各自保留源文本不超过32*1024*1024个UTF-16 code units（JS string.length，非字节或Unicode字符个数）。预算计算针对驻留的数据，重复访问不是新增数据。恰好到边界允许驻留，单份超过预算仍完整展示但不驻留；淘汰或换代后的重算合法。不能靠禁用缓存、无条件全量清空、永久保留、截断内容或吞错误规避约束。

## 运行边界
使用随包 runtime/node（也可 npm scripts）。src/ 的纯业务函数来自真实历史代码，去掉了React类型/UI壳并导出；runtime 为固定第三方依赖，scripts 为模块解析与加载检查。没有新造异步调度器，不模拟 React/Electron、网络或真实设备；不能凭这些检查声称帧率或端到端时延改善。计分按输出与确定性工作量/驻留行为，不要求特定写法。工具内部实现变化导致外部观测无法适配时应人工复核，不自动计零。
