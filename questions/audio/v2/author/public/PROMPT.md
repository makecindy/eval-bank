# 连续录音偶发波形失真

语音输入收到的 PCM 偶尔出现不应有的零值或波形失真，短的单次输入不容易发现。不同设备采样率、浏览器采集路径和回调分块方式下表现不一致。

这里提供故障发生时的完整音频引擎、worklet 与上下文池源码。请自行定位原因并修复所有受影响的音频转换路径，保留已有接口与生命周期语义。无需改麦克风权限、连接状态管理或识别服务。

验收要求：
- 有限 Float32 单声道输入，设备采样率 8/16/32/44.1/48 kHz，输出 16 kHz PCM16。沿用源码已有的采样与量化规则；同一段连续音频的输出不能随回调分块方式变化。采样时刻从录音起点开始，同率保留全部样本；非同率不为缺少后续原始样本的末端位置补点。数值比较允许一个 PCM 单位误差，样本数必须准确。
- 同时覆盖 AudioWorklet 与 ScriptProcessor fallback；不能只让两条路径输出相同的错误结果，也不能以静音、删除异常样本或改变输出时长掩盖问题。
- 保留各自默认和显式配置的帧长、PCM 正负削波、trace 字段及连续帧序号。暂停/恢复和新一轮录音不能混入不应保留的音频。
- 排空可重复调用，也可以排空后继续送入音频，不得重复或丢失已经可以转换的样本。worklet 的 flush 回执须保留原始 ID，即便没有音频；reset 丢弃它尚未发出的旧尾部。fallback 的 stop 保留现有“先发出尾部再清空状态”的行为。
- 检查包含长短音频、单样本回调、不规则回调、worklet 的空回调和两轮录音。设备采样率在一轮录音内固定。不验证真实浏览器、麦克风或 ASR 效果。

只允许修复 WebMicAudioEngine.ts 和 pcm16k-worklet.js。audioContextPool.ts 为只读依赖。不要查看其他目录、历史提交、以前的模型答案或本次私有评分器。

提交方式：不要写任何文件，不调用 bash/edit/write，不委派或寻求解题提示。最终只返回一个 JSON 代码块，格式为 {"edits":[{"file":"文件名","old":"原文","new":"替换内容"}]}。每个 old 必须在当时文件中恰好出现一次；按 edits 顺序应用。可以含多个文件和多处修改。评测端机械应用，不替你修补或重试。
