本题保留历史接口的以下既有约定，输入组合可变化，实现方式不限：

- 正文已经显示后，历史页恢复、流式内容增加、完成消息的持久化通知与历史页先后到达，都不能让后续正文插到前一段上方。每个段落应恰好显示一次，增量属于原段落；结束后由历史接管。源消息的时间和内容不能被展示逻辑伪造或回写。
- 共享历史视图接受本地待发送/阻塞用户气泡。这些用户气泡来自当前 UI store，不能依赖设备时间把它们移到历史前面。正文交接重排时，本地气泡仍占据对应的上下文插入位置，用户气泡之间保持顺序；从 store 移除的气泡不得复活。比如可见顺序“旧正文、用户甲、正文一、用户乙、正文二、用户丙”在正文一持久化通知导致原始 store 两段正文顺序改变时，仍保持相同阅读顺序。该合同来自共享历史渲染器，不能用手机端没有 outbox 替代它。
- 子 Agent 正文仍属于对应子卡片，适用同样的流式保序、完整性与不重复约定。正常嵌套保留卡片；原实现对过深嵌套提供平铺回退，此回退也不能丢失或打乱原本顺序。跨子卡片的任意全局重排不是要求；同一可读序列及回退序列需要保序。
- 没有历史视图的旧手机消息渲染入口仍接受按时间乱序的原始数组，保持原有按时间展示行为。不要把本次修复变成所有入口无条件按输入顺序展示。


依赖、宿主或验收环境本身导致无法执行时记不可评分；候选改动引起的构建失败若使全部行为不能执行，则无法执行的行为失败，并注明构建失败。并非把基础环境错误算作模型零分。这里没有模型难度预设或最低分要求。

同一会话内上述约定可以反复交错发生。持久化时间可改变，但不是新段落的阅读顺序；允许以真实页面顺序与已观察身份交接，不能伪造源时间。新增场景不引入删除、分页或本地用户协议之外的约定。
