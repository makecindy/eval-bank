# 历史评测公开摘要

本目录为历史结果的脱敏结构化导出，不是新一轮评测。

- `../results/historical-records.json`：346份历史评分记录，含导入与复评，不能当成346份独立作答。
- 三份 `seven-*/summary.json`：同一七题试卷、简短提示条件下的Luna high、Grok high与MiMo试跑摘要；每题各一次，不是统计显著性结论。
- 保留原始精确分数、题目修订、样本类型和执行通道；不跨修订合并排行。
- 原始证据仅私存。本导出不包含工作区、用户消息、provider账号ID、数据库、路径或凭证，不能单独重建全部历史运行。
- `costUSD: null` 表示本记录缺少可用实际费用证据，不等于免费。历史公开单价估算不混入实际账单字段。
- 当前开发版受审批异常影响的样本仍在复核/补跑，未混入这批已封存历史摘要。

导出命令：`python3 scripts/export-history.py /path/to/private/archive /path/to/export`。脚本使用显式字段白名单；输入须为本项目受信的历史归档，公开前仍需人工审查字符串内容。原件哈希用于核对来源，不公开原件路径。

输出目录必须与私有归档互不包含，输出文件不得通过符号链接或硬链接指向原件。记录必须恰好覆盖已封存的 346 个唯一 runId：脚本固定条数及排序后 ID 数组的 SHA-256，不从可变的输出文件推导集合。缺失、多余、重复或同数量换入其他 ID 都在写入前拒绝；更名或调整源文件枚举顺序不影响集合校验。该摘要只验证集合成员完整性，不证明同 ID 的记录内容未变；分数仍按原值导出，不重算。全部记录、三份摘要和输出路径均先校验再写入，输入缺失或格式错误时保留现有公开文件。本工具不接收新增历史运行，追加需另行审阅，不能通过改输入绕过封存边界。`items` / `regressions` 只接受已审查的考核点 ID 与布尔值（或原有 null）；新考核点需先更新脚本白名单，不能把任意诊断内容直接公开。

导出安全回归：`python3 -m unittest discover -s tests -v`。测试使用合成归档，不读取私有原始日志。

### 执行边界

这是维护者手动运行的本地导出工具，不是接收不可信路径的服务。归档、输出目录及其父目录必须由可信用户控制；运行期间不得由其他导出进程、同步工具或其他进程改写、移动或替换这些目录。先暂停相关写入，再导出到独立目录，审阅产物后提交。

命令行选择的归档和输出根目录会先解析为规范路径；允许根目录自身或其祖先使用别名（例如 macOS 的 `/tmp`），实际写入的是解析后的输出根。解析后与归档相同或互相包含的输出根仍会被拒绝。此行为不承诺拒绝命令行路径中的所有符号链接；维护者须确认所选根目录最终指向自己的独立审阅目录。

规范输出根下由脚本派生的 `results/`、`reports/` 路径及目标文件不得含符号链接，即便链接指向与归档无关的其他目录也拒绝；已有目标文件的多重硬链接同样拒绝。路径检查不能防御检查后被其他进程替换目录的竞态；逐文件替换也不提供多文件事务或断电回滚保证。如果不能保证目录在运行期间不变，不应运行此工具。此 PR 不引入目录锁、对抗并发篡改的文件系统沙箱或无人值守导出服务。

归档内的记录或摘要也可能通过文件、祖先目录别名落在输出树中。因此四个输出目标还必须与全部 346 个记录及三份摘要分别不是同一个文件，检查在创建目录或暂存前完成。比较设备号及 inode，不只比较路径字符串，也覆盖大小写不敏感目录中的同文件拼写别名，防止替换脱敏产物时覆盖原件。指向其他独立原件的输入别名仍允许；这不增加运行期间目录置换的防护承诺。

文本输入与导出固定为 UTF-8。导出器新建的目录使用 `0755`、新文件使用 `0644`；已有目录不修改，替换已有文件时仅保留 POSIX mode 权限位。替换产生新 inode，不保证保留原属主、属组、ACL 或扩展属性。输出应位于维护者拥有的独立审阅目录，不能直接指向依赖这些访问策略的线上目录；审阅后由既有发布流程设置目标访问策略。如果已有父目录限制其他用户访问，导出器不会放宽它们。

记录必须包含非空的运行/模型/题目修订身份、64位 manifest 哈希、已知状态和 scoreExact 字段。环境无效（environment_invalid）记录必须无分：scoreExact 为 null，score 缺省或为 null；带任何非空分数（包括零分）都在写入前拒绝，不自动清空或改分。正常评分（graded）记录及摘要每题须提供合法的精确分数字符串；可选 score 缺省或 null 保持，非空时须与精确分数一致。缺字段或错误类型不补成有效成绩。精确分数仅校验格式和每题 0–1 范围，不重算、不改写。摘要 failedItems 只接受该题在本批历史中已审查的 ID 列表（允许空列表），拒绝路径、诊断文本或嵌套对象；未来新 ID 必须先审查扩展白名单。自由文本仍需公开前人工审查，类型校验不等于自动脱敏。

记录的 sampleKind 只接受本批已封存的 independent、historical_import、reassessment、assisted_revision 四类；两种记录状态均在写入前拒绝未知值、大小写或空白变体，不推断、规范化或重写分类。此检查只保证类别合法，不证明该 runId 的分类与私人原件相符；独立样本、导入与复评仍须按原始证据区分。

三份摘要目录分别绑定已封存的模型与 effort，以及共同的试卷、提示条件、fast 和 timeLimitInPrompt 值；摘要放错目录或实验身份不符时拒绝导出，不改写元数据来迁就目录。可选的题目 name、executionChannel 和摘要 promptNormalization 只接受字符串，limitations 只接受字符串数组；缺省字段保持缺省，错误类型在写入前拒绝，不静默丢弃或转换。该工具只导出这批固定历史报告，不按新模型或新实验动态扩展。

字段之间的明显矛盾也在写入前拒绝：记录同时提供 startUtc 和 endUtc 时，按带时区的实际时刻比较，结束不得早于开始；相等、缺省、null 或仅一端时间均保留原值，不补造时长。摘要每题的精确分数等于 1 时，failedItems 必须为空；不从空失败列表反推满分，也不按失败项重算分数。

记录的 configurationId 必须与 model、harness、effort 三字段一致；仅接受本批已存在的 ` / `、`/`、`|` 三种分隔格式，模型名自身的 `/` 保持原义，输出不规范化或改写。questionId 与 revision 共同选择一份固定历史 rubric：manifestSha256 必须等于该组合已封存的公开哈希，`items` / `regressions` 也只接受同一 rubric 下各自的许可 ID，不能借用别题、别版或另一字段的身份。11 份 rubric 的哈希与诊断集合由脚本中的同一常量表维护，运行时不从输出文件建立基准；正常评分和环境无效记录均在写入前检查。未包含逐项诊断的旧版本仍允许缺省、null 或空字典，拒绝非空诊断；未知题目修订须另行审阅。该关联校验不证明同一 runId 的内容与原件完全相同，也不根据诊断项重算分数；七题摘要继续采用独立的 failedItems 合同。
