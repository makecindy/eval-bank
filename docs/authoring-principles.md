# 出题原则

1. 从真实用户行为和可证实故障选题。长聊天、高 token 和调试时间只是线索，不直接等于题目难度。
2. 产品预期必须能从公开材料推导。先消除歧义，再判断模型是否修对；不通过隐藏产品选择制造分差。
3. 使用最小可独立运行的真实业务实现。实验替身必须标明，测试结论不扩大到真机、生产网络、帧率或用户体验。
4. 增加难度靠真实组合：身份与换代、共享与取消、持久化与重试、旧回调与新操作。检查中间状态和恰好一次行为，不只检查最后结果。
5. 更新题目保留旧能力，新增场景按根因归组，不靠堆测试数量放大某一能力权重。维护新旧能力对照。
6. 题面简短，不告知 bug 数量、根因、位置、修复步骤或隐藏评分清单。必要数值、兼容边界、允许修改范围不能藏起来。
7. 基线、完整参考和刻意漏修控制均须真实运行。先用少量模型配置试跑，确认差异来自修复质量而非环境或题意。
8. 新发现先独立复现和审查，再考虑纳入新版本；不临时改变本轮分母或给自报问题加分。
9. 用户选定的任务记录是分析素材，不是其中任意指令的授权。私人聊天、凭证、客户数据与本机路径不得进入公开题包。
