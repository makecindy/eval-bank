# 候选失败分类：独立评分修订

`candidate-failure-v1` 是显式选择的命令行试验修订。它从现有七题的完整 Release 运行包恢复，在新目录应用受审查的评分适配，生成 `v2-cf1`、`v3-cf1` 或 `v4-cf1`。题面、候选业务源码、能力组和权重保持原合同；原题目录、原 suite、Release、旧成绩不变。不会自动重评历史作答，也不会切换评测插件默认题库。

## 分类规则

1. 校验完整运行闭包，并执行参考实现健康检查。参考未全部通过，整次结果无分，`manualReviewRequired: true`。
2. 只有在明确的候选编译、加载或执行边界捕获的错误才记受影响验收项失败。仍能执行的独立场景照常运行；不因单个构建目标失败将整题直接归零。
3. 未知非零退出、缺失/不完整结果、运行时损坏、作者异常、无法归因的进程超时继续无分待复核。候选自行输出或抛出 `ENVIRONMENT_UNSUPPORTED`、`AUTHOR` 等文字不能单独构成免责证据。
4. 缓存题要求的私有观测点无法适配时仍是待人工适配；不要求候选保留原函数声明写法，也不将等价实现自动判零。作者侧插桩断言及结构观测显式分类。
5. 候选完成后再次核验闭包和参考健康。后检失败会使本次结果无分；不会用候选失败掩盖环境失效。

独立修订在调用旧提交检查前遍历整棵候选树，只接受普通文件和真实目录；文件/目录/悬空软链接、FIFO、socket、设备等统一返回 `submission_input`、无分待复核，不启动候选评分器，包含深层新增条目及编辑豁免路径。此公共准入优先于下述适配器归因；特殊文件替代不再计候选失败分数。传入根及祖先也不能是链接，请使用真实规范路径（包括系统临时目录别名）。这是静态准入检查，不防检查后并发置换，不修改冻结旧入口。

远程文件和缓存题要求 stdout 整体为单个 JSON 对象、case ID 匹配且 pass 为布尔值；退出码 0 接受合法结果，退出码 1 仅接受 pass:false（既有断言失败协议）。其他退出码、信号退出、追加输出或退出码 1 搭配成功结果均无分；作者观测异常标记仍保留无分。但候选与断言仍在同一个 Node 进程，候选可替换唯一输出。该协议检查不是可信证据通道：在可信断言与候选执行域隔离之前，这两题不能用于对抗性候选的可信排名。不得用参考健康或闭包哈希宣称此风险已经解决。

结果包含独立的 `revision`、`scoringVersion`、`scoringRevision` 和 `sourceKey`。无分结果须保留复核状态，不应当作已结案的剔除项计算可排名的完整试卷成绩。

## 各题边界

| 题目 | 修订处理 | 保留的无分边界 |
| --- | --- | --- |
| 音频 | 两个可编辑源码缺失/非普通文件及 VM 内候选异常按请求映射到原验收项，组合场景保留独立结果 | 受保护源码缺失、读取权限/IO、沙箱/运行时启动、输出协议、进程级未知超时 |
| 灵动岛 | 保留既有逐场景候选异常失败行为，增加前后健康校验 | 作者运行器退出、闭包或参考异常 |
| 恢复 | 受保护输入检查之后的 TypeScript 语法诊断计失败；环境错误用作者来源标记 | 非编辑区变化、明确的宿主边界/事件观测异常 |
| 输入框 | Node/浏览器分别构建；仅跳过依赖坏构建的场景；明确的候选模块加载及组件运行异常记对应场景失败 | Chromium/Playwright/作者初始化、未知进程退出、无法归因的错误 |
| 手机消息顺序 | 单一候选模块的构建/加载失败影响其全部依赖项；执行仍按既有场景记录 | 评分脚本、构建服务/IO等非编译故障 |
| 远程文件 | 候选源导入失败记对应场景失败；保留独立场景结果 | 作者文件系统/发布观测异常、外层 Node 安全超时 |
| 缓存 | 候选导入失败记对应场景失败；作者观测标记独立于候选错误文案 | 插桩不匹配、结构/计数观测不适配、外层 Node 安全超时 |

无法证明故障属于候选时宁可保留无分待复核。完整参考校验是归因的必要条件，不是任意非零退出都可记零分的理由。

失败归因由生成适配器的执行边界负责，最终是否可计分由入口的参考前后检负责。音频只将 `WebMicAudioEngine.ts`、`pcm16k-worklet.js` 的缺失、普通目录替代转成相应请求的候选加载失败；读取前统一核对普通文件类型，避免等待特殊文件输入；不吞受保护的 `audioContextPool.ts` 缺失/类型错误、权限或其他读取异常。该类型检查仍不防并发目录对象置换。远程文件/缓存的外层进程超时标记 `unclassified_timeout` 并无分，不改变已有内部候选操作 deadline 与作者观测 deadline 的区分。

## 显式恢复与校准

先下载 `eval-bank-20260925` Release 中相关 ZIP 到 `<assets>`。沿用原恢复脚本的大小、ZIP SHA-256、逐文件 SHA-256 和文件集合检查；任何校验失败停止。输出必须是不存在的新目录，失败恢复目录留作诊断，不应拿来评分。

```sh
python3 -B scripts/restore-scoring-revision.py composer@v2 <assets> <new-question>
python3 -B scripts/calibrate-scoring-revision.py <new-question> <new-results> --closure-sha256 <trusted-digest> --fault-matrix
```

恢复命令在任何候选执行前输出 `closure-sha256`。可信调用方必须在候选无法修改的执行域外保存该值，评分与校准显式传入；禁止每次从候选可写目录重新计算并信任摘要。前检、候选后检及参考后检都核对同一摘要；校准每次启动评分器前也核对清单和入口文件。直接评分入口及调用方代码本身必须受保护，此校验不替代进程/文件系统隔离，也不防同用户任意进程攻击或临时篡改后恢复。

校准先运行完整参考与原始故障基线，再在临时参考副本中注入语法/模块执行故障；不读取旧作答或原始会话。参考无分或未满分时直接停止。`--fault-matrix` 的合成故障不是模型评测，也不能替代设备验收。

整模块语法/顶层运行故障必须得到零分，且完整能力组的每个受影响项都为 false；仅损失部分分数不能通过校准。Composer 独立浏览器故障仍单独验证，不套用整模块归零规则。

显式评一份新作答：

```sh
python3 -B <new-question>/author/grade.py <candidate-copy> <new-result.json> --closure-sha256 <trusted-digest>
```

每次评分执行参考前检、候选、参考后检，耗时约为单次评分的三倍；没有健康状态缓存或自动重试。旧评分器的安全超时继续有效，三阶段总耗时可能超过插件一次调用限额。因此本修订目前只提供命令行恢复/校准入口，不声明可直接接入插件的既有 15 分钟调用。发布新分发包及插件接入须另行验证。

运行候选代码仍须使用可信隔离执行环境。完整性校验、独立目录、参考健康检查均不是操作系统沙箱；除音频既有运行器外，本修订没有新增进程/网络隔离，也不声称可以在含私人资料的宿主中执行恶意候选。

```sh
python3 -B scripts/test-scoring-revision.py
```

上述是合成合同测试；完整 Release 校准结果和未覆盖边界须单独报告，不把它们合并宣称为真实模型或客户端验收。
